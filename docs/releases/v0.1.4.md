# v0.1.4

## Highlights

- The desktop can preview local and remote files, browse directories, and show
  Git status over a read-only Files service. Closing a preview cancels its
  pending request while other operations continue.
- The CLI and desktop can import self-contained OpenVPN client profiles with
  optional credentials and use them for local VPNs and remote routes.
- The desktop offers System, English, and Simplified Chinese in **Settings →
  Language**. Windows gets portable desktop packages for x64 and ARM64, plus
  complete runtime installation and SSH deployment for x64.
- Use `CTL_DATA_DIR` to isolate installations, history, and daemon state, or
  `CTL_CONFIG_DIR` to separate settings while sharing the selected data root.
- The updater organizes complete runtime builds by channel and target.
  `ctlup component list` shows installed target membership and `ctlup show`
  lists individual builds and their active or rollback status.

## Upgrading

- For Cargo installations, add the separate `ctlup` package alongside
  `ctl-cli`. The command still runs as `ctlup`. [Cargo installation instructions](../publishing.md#install-published-commands)
- Run `ctlup migrate` with the new updater to adopt an existing complete
  installation into the channel catalog. It preserves active and rollback
  selections and running-process leases. Replace incomplete historical
  four-service builds with a complete installation before adoption.
  [Migration details](../component-updates.md#desktop-and-migration)
- Use `ctlup dev --app` for the desktop source builds previously handled by
  `ctlup app install --local` and `ctlup app update --local`. The app install and
  update commands install published releases. For Linux x64 or ARM64 checkout
  deployments previously run with `update --working-tree`, use
  `ctlup dev --host NAME`, `ctlup dev --hosts work,lab`, or
  `ctlup dev --destination ALIAS`. `ctlup dev --renew-signing` renews the
  active macOS development helper signature without rebuilding.
  [Development builds](../local-bundles.md)
- Upgrade the relevant broker and agent before using OpenVPN over SSH or
  remote file previews. An older client cannot read a saved VPN profile
  document containing an OpenVPN profile.

### Changes since v0.1.3

- `ctld` advances from `1.2.18` (build 18) to `1.3.20` (build 20).
  Contract `1.3.19` adds the Files service to `open_service`. Contract
  `1.3.20` adds OpenVPN to VPN start requests and connection responses.
  Earlier selections retain their existing services and VPN providers.
- `ctl_remote_vpn` advances from `1.1.2` (build 2) to `1.2.3` (build 3).
  The new contract accepts the OpenVPN provider with a bounded self-contained
  profile and optional credentials. Earlier selections retain OpenConnect and
  Tailscale behavior, and `1.1.2` retains client identity selection.
- `ctl_transport` advances from `1.0.1` (build 1) to `1.1.2` (build 2).
  The new contract adds service selector 3 for Files. Selectors 0–2 retain
  their existing meanings under both contracts.
- `ctl_files` starts at `1.0.1` (build 1) with bounded read-only `metadata`,
  `read_file`, `list_directory`, and `git_status` operations. Each logical
  stream carries one independently cancellable request. Older agents retain
  eligibility for their existing services.
