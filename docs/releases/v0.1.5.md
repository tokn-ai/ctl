# v0.1.5

## Highlights

- `ctlup` keeps the updater, desktop, and runtime builds together under
  `~/.tokn/ctl/ctlup/`. New installs use readable build labels. Runtime builds
  group targets under the build label, and the local desktop and updater use
  one directory per build.
- Use `ctlup install` to provision a machine or choose a source, `ctlup update`
  to follow the installed channel, and `ctlup status` to inspect selections and
  missing builds. An update can repair a missing build from its exact verified
  cache, and pinned sources stay on the selected build.
- Remote updates reuse verified files where available. If the local cache has
  the target updater or runtime archive, the app can send it over SSH. For
  missing files the remote host tries curl, then wget. The app can download
  and upload the same release when the remote download is unavailable.
- The desktop can install Windows x64 components from the SSH connection
  prompt. VPN engine subprocesses no longer open console windows on Windows,
  and idle terminal heartbeats save last-seen timestamps in the background
  without displaying **Saving workspace…**.

## Upgrading

- v0.1.5 starts a new installation registry, and the old `ctlup migrate`
  command is retired. On Unix, the old managed launchers occupy paths needed
  by the new installer. For a local install, set `CTL_DATA_DIR` to a fresh
  absolute path before installing and use that profile when launching the
  new build. Keep the previous profile for its settings and existing sessions.
  Before provisioning an existing Unix SSH account, move its old ctl-managed
  command launchers out of `~/.tokn/ctl/bin/` and keep them as a backup.
  A new SSH account can be provisioned directly.
- Start with the standalone `ctlup` for your platform from this release.
  Use `ctlup install app --channel stable` for the desktop app.
  On Linux and Windows x64, `ctlup install --channel stable` installs the local
  runtime. On macOS, use the bundled CLI from the release or build the managed
  runtime with `ctlup dev` and a signed helper.
- For saved remote accounts, use `ctlup install --channel stable --host NAME`.
  For a new SSH destination, use `--ssh ALIAS`. For a Windows x64 address or
  alias, add `--remote-platform windows` and use the server's default
  `cmd.exe` shell.
- To build from source, run `ctlup dev` or `ctlup dev --app` from the root of
  the ctl checkout you want to build. Use `--workspace PATH` to select a
  different checkout explicitly. `ctlup dev sign` renews the active macOS
  development helper signature.

See [component updates](../component-updates.md) and
[local development builds](../local-bundles.md) for command examples.

The updater advertises storage layout 7. SSH provisioning requires a target
updater that supports that layout. The build inventory advances from schema 1
(`ctlup-show-v1`) to schema 2 (`ctlup-show-v2`), which adds exact active-source
information and missing-build records. Activation verification retains
`ctlup-command-v1`. These updater contracts have no internal protocol builds.
See [protocol versioning](../protocol-versioning.md) for the storage and
transfer contracts.

## ctream preview

ctream is available through the separate
[preview workflow](https://github.com/tokn-ai/ctl/actions/workflows/ctream-preview.yml).
Use `ctlup ctream install` to install it. The preview supports Linux X11 and
Wayland, Windows display and window streaming, macOS window streaming, and
viewer diagnostics. The latest `ctream_agent` contract is `1.0.11` (build 11),
with `1.0.1` through `1.0.10` retained. It adds macOS window discovery, capture,
and input to the earlier Linux and Windows contracts. The preview crates use
their separate `0.1.0` product version.
